CrowdGPT is an open federated training protocol. You run a client on your machine, train on a data chunk locally, submit the weight delta, and the global 0.6B-parameter transformer gets better. No datacenters required.

Federated pretraining, in the open.

A single company training a frontier model uses thousands of A100s in a datacenter. Most people don't have that hardware. But millions of people have gaming PCs with RTX cards sitting idle. CrowdGPT pools that compute, and the model that gets trained belongs to everyone who helped build it.

01

Local training, local data.

Your GPU trains on a 1MB data chunk fetched from HuggingFace. The weight delta is the only thing that leaves your machine. Nothing else.

02

A real architecture.

500M-parameter dense transformer with grouped-query attention, SwiGLU, and RoPE. Same building blocks as Llama and Mistral, just scaled to run on consumer hardware.

03

Auditable end to end.

The client is a single Python file. No binaries, no telemetry. Read it, fork it, run your own coordinator. The model weights are downloadable.

A note on trust

Every submitted delta is validated server-side before it touches the global weights. Malformed, oversized, or statistically suspicious updates are rejected automatically, and repeat offenders lose write access. The server never executes anything a client sends; it only ever reads numbers. This makes the global server/coordinator immune to any breaking attacks.

Install the client

Get up and running in under a minute. The client is a single Python script with minimal dependencies.

Quick start Recommended

Clone the repository, install dependencies, and run the client. It will automatically detect your GPU and configure optimal settings.

bash

The Federated Protocol

How CrowdGPT coordinates thousands of independent GPUs to train a single, cohesive language model without centralizing data.

1. Task Assignment

When a client connects, the coordinator assigns it a specific data shard (a local chunk of tokenized text) and the current global model weights. The client downloads the weights from HuggingFace (or the coordinator) and loads the data chunk locally.

2. Local Training

The client performs a set number of forward and backward passes on its local GPU. It calculates the gradient (the "delta") between its starting weights and the newly trained weights. No raw data ever leaves the client's machine.

3. Secure Submission

The client compresses and submits only the weight delta to the coordinator. The coordinator validates the submission:

✓Checks for NaN or Inf values in the delta.
✓Verifies the delta size matches the model architecture exactly.
✓Ensures the delta norm is within statistically acceptable bounds to prevent poisoning.

4. Sequential Aggregation

Valid deltas are applied to the global model using a decoupled learning rate and weight decay. The global step increments, and the updated weights are periodically pushed to HuggingFace for public auditing and as a bootstrap for new clients.

Is my data safe when I run the client?
Yes. The client downloads a public, anonymized data chunk to your machine. Your personal files, browser history, or any other local data are never accessed or transmitted. Only the mathematical weight delta is sent to the coordinator.
Can I run this on a CPU?
Technically yes, but it will be extremely slow. The client is optimized for CUDA-enabled NVIDIA GPUs. If no GPU is detected, it will fall back to CPU, but contributing meaningful compute will take significantly longer.
How are malicious updates prevented?
The coordinator enforces strict validation. Every submitted delta is checked for NaN/Inf values, exact size matching, and norm bounds. Updates that deviate too far from expected statistical distributions are rejected, and repeat offenders are temporarily banned by subnet.
